## 数据与事务

- Prisma6.19.0、NestJS11；数据库有品牌、门店、授权员工、会员、SHA256哈希开发会话、分类/商品/SKU/加料、桌号、报价、订单快照、事件、现金流水、审计和版本化CMS。
- quote服务端读取价格、商品归属、加料归属及库存；金额为有界整数分，单行数量1..99。加料去重、不同加料组合独立保留；不支持的券明确拒绝。报价5分钟有效；提交时再次检查价格、门店营业/服务规则与库存。
- 创建订单、条件扣可售库存并预占、事件同一 Serializable 事务；唯一(userId,idempotencyKey)绑定请求hash，quoteId唯一，最多5次并发重试。重复相同请求返回原订单，复用键换请求返回STATE_CONFLICT。库存修改先聚合加料与SKU数量，再按固定ID顺序锁定，取消/收现金/超时任务采用相同顺序。
- 取消/拒绝未付款订单仅释放一次预占；重复取消安全。现金收款要求有门店授权、实收>=总额；现金流水orderId唯一，找零与付款状态/库存消耗/审计/事件原子提交。已付款取消/拒单明确REFUND_UNAVAILABLE，不直接抹掉收款状态。
- SKU stock表示可售库存；编辑不覆盖reserved。SQL CHECK保证非负库存/预占/金额、库存总量、现金找零、订单金额恒等式及订单付款状态一致性，越界输入在HTTP层拒绝。
- 订单金额、商品名、规格、加料是下单时快照；之后商品修改不会追改历史订单。桌号OCCUPIED由同门店未完成堂食订单实际推导。

## 安全、隔离与读模型

- 仅固定customer/owner/clerk-a/clerk-b可开发登录，必须非production且DEV_AUTH_ENABLED=true，并查询真实体验品牌账户。32字节随机token只存hash，12小时过期。生产启动出现DEV_AUTH_ENABLED=true或DEV_SEED_ENABLED=true直接失败；生产不采用数据库默认回退、不注入体验数据、不伪造微信登录。
- 顾客只读/取消自己的订单；员工按角色、品牌、storeIds授权。店员只能改门店营业状态；商品/价格/分类/CMS等写入及员工列表要求owner。白名单拒绝额外字段。会员从实际用户表读取，手机号脱敏，余额与积分为实际记录（体验初值0）。
- 公开数据通过PUBLIC_BRAND_ID选择单一品牌；仅有一个品牌可自动选择，多品牌未配置则503，不能公开遍历其他品牌。
- 商户概览读取数据库现金收入、成功退款、订单状态与低库存；经营日使用Asia/Shanghai边界，数据时间UTC。R1无法产生成功退款，所以实际退款聚合为0，未伪造退款记录。
- CMS草稿持久化并递增版本，发布带expectedVersion条件；公开配置只读已发布JSON。商品/门店/SKU/现金/状态/CMS写入有审计，不保存密钥或密码。

## 明确限制与风险

- 微信登录、微信支付、退款尚未实现真实外部集成；配置了环境变量也不会假装可用。现金付款是员工人工确认实际收款。无生产身份注册/密码初始化通道，生产身份接入与首位管理员受控初始化需另行实现验收。
- 配送报价统一503 INTEGRATION_UNAVAILABLE；种子只开放堂食/自提。配送范围、地址校验、配送商/骑手、设备、打印机等未接入。
- 商品在R1归门店；分类归品牌。品牌通用商品模板、门店覆盖等未实现，不能标记为完整品牌商品架构。
- 未付款订单15分钟到期；启动时及每30秒扫描最多100单，事务关闭并只释放一次库存，现金收款拒绝过期订单。多实例并发扫描及重复扫描已测试。生产仍需补齐对账/监控、身份接入、会话限流等运维能力。
- 统计当前只有现金渠道；无真实微信流水。无优惠券实现，传券明确失败。现金退款未提供，避免伪造退款结果。
- Windows运行中的Prisma原生DLL会锁文件，执行build/prisma generate前需先停本项目API再启动。Prisma package.json配置弃用警告不影响6.19执行。
