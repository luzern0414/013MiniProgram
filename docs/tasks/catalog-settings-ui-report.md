# 分类与单位维护 UI 实施记录

日期：2026-10-20；基线：`6ba9ffb`。本记录仅涵盖 Task 2 前端、共享行为与构建；浏览器真实写入、SQL/审计、低权限和顾客报价链路由协调器独立验收，结果另记验收台账。

## 已实现与实际边界

- Web「商品与库存」和商户小程序「商品」提供真实「分类与单位」维护。分类展示引用商品数、排序、启停和可见门店；分类/单位真实新增、编辑、停用、删除，删除前确认。创建合约只接收名称，默认启用；创建后编辑可设置其他字段。
- `canManageBrand=false` 显示只读列表与权限提示，无新增、编辑或保存入口。API 仍负责最终授权。
- 分类门店范围精确区分 `null`（全部当前和未来门店）、指定数组、`[]`（全部隐藏），不将空集合转成全店。分类改名与单位改名/启停后组件发出 `changed`，Web `useResource.reload`、mini 既有 `refresh` 重新读商品，因此列表单位/分类名称同步更新。
- Web 商品编辑移到独立 `ProductEditor.vue`；商户小程序新增独立 `ProductsPanel.vue` 和 `ProductEditor.vue`，支持真实新增及基础编辑。商品新建1至20种规格；已有商品编辑只 PATCH 基础字段，不发送 `skus`、不重建/删除 SKU，不调整原库存。原售罄切换及 Web 独立价格/库存管理保留。
- 两端商品编辑都读取 settings，保存前再次读取最新 settings。改选分类只允许启用且本店可见分类；改选单位只允许启用单位。原有停用/隐藏分类或停用单位可保留；未改分类省略 `categoryId`，未改单位同时省略 `unit`/`unitId`。加载失败阻止保存，无自由文本降级。
- 共用有限状态 controller，复用 Web `api`、mini `createClient('merchant')` 和现有会话。`STATE_CONFLICT` 锁定写入，必须重读后核对；`NAME_CONFLICT`/`REFERENCE_CONFLICT` 提示原因且保留表单。网络、超时、异常返回、`INTERNAL_ERROR` 等未知写入结果锁重发。
- 商品未知结果恢复先 GET 真实商品列表：已有商品读到最新商品与 settings 后重新填写；新建结果未知则读列表后关闭编辑器供核对，不直接再次 POST。恢复读取失败继续锁定。分类/单位新建未知结果同样重读并返回列表核对。
- 小程序写入时同步上报 `busy`，父页面锁定切店、底部导航、退出和其他经营操作；编辑器禁止关闭及重复提交，沿用 `locked`/待恢复现金限制。门店读取/写入完成检查原门店 scope，旧门店结果不写入新门店状态。
- Web `CATALOG_CHANGED` 明确提示「分类已调整，请刷新商品后重新确认。」并有行为测试。
- 沿用 Web Modal（含现有动画/减少动画规则）、uni 底部 overlay/sheet；小程序文字输入用 AccessibleInput，H5 原生 label 可定位并点击聚焦，微信业务逻辑不依赖 DOM。新增样式最小14px，标题24/28px。没有增加另一套请求、会话、弹窗或动效框架。

## 推荐真实验收定位与准确标签

Web：5173，侧栏「商品与库存」。

- 入口「分类与单位」（展开后「收起分类与单位」）；切换「商品分类」「售卖单位」；刷新「刷新分类与单位」。
- 「新增分类」→「分类名称」→「保存分类」；单位对应「新增单位」「单位名称」「保存单位」。
- 列表操作视觉文本「编辑」，aria-label 为「编辑{名称}分类」或「编辑{名称}单位」。编辑分类字段：「启用分类」「排序（数字越小越靠前）」「全部门店可见，包含未来新门店」「可见门店（不选则全部隐藏）」，门店选框使用真实门店名。单位开关为「启用单位」。
- 删除按钮「删除分类/删除单位」，确认按钮「确认删除分类/确认删除单位」，取消确认「保留」，关闭表单「取消」。
- 商品按钮「新增商品」或行「编辑」（aria-label「编辑{商品名称}」）；字段「商品名称」「分类」「售卖单位」「商品描述」「商品图片地址（选填）」「上架售卖」；新建规格字段「规格名称」「售价（元）」「可售库存」，按钮「添加规格」「移除规格」「保存商品」。
- 冲突/未知结果恢复按钮「重新加载并核对」。原单位/分类不可选时出现「（保留原单位）」「（保留原分类）」选项。

商户H5：5175，底部「商品」。

- 同名「分类与单位」「商品分类」「售卖单位」「新增分类/新增单位」，设置刷新按钮为「刷新设置」。
- 名称、排序输入可用 AccessibleInput 的精确 label；分类全店开关标签「全部门店可见（含新门店）」；其他门店选框和保存/删除/确认/恢复文案同上。
- 商品「新增商品」「编辑{商品名称}」；分类 picker 的可访问按钮标签「选择商品分类」，单位为「选择售卖单位」，打开后通过 uni picker 选择真实名称、确认。初始包含「请选择分类/请选择单位」占位，选择后才可提交有效ID。
- 名称/描述/图片输入标签同Web。新建规格精确标签「规格1名称」「规格1售价（元）」「规格1可售库存」，其他规格数字依次递增；「移除规格1」「添加规格」「保存商品」。
- 建议重点验收：Web新增分类/单位→新增商品→商户H5刷新读到→改单位名两端列表即时更新；分类仅一家门店可见与全部隐藏；引用删除保留错误与编辑；移动商品分类解除旧引用后删除；停用当前分类/单位仍能只改商品名；新商品不能选已停用/隐藏选项；两浏览器同版本冲突后锁定；网络响应丢失后的重读核对；慢写入期间切店/导航/关闭被锁定。
